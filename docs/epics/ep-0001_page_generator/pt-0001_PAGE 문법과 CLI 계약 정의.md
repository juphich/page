# pt-0001 PAGE 문법과 CLI 계약 정의

## 목표

구현의 기준이 되는 `page:gantt` 입력 문법과 CLI 동작 계약을 확정한다.

## 작업 내용

- 필수 필드, 선택 필드, 기본값과 날짜 의미를 정의한다.
- 입력·출력 인자, 덮어쓰기와 종료 코드 정책을 정의한다.
- 오류와 경고의 구분 및 위치 표시 방식을 정의한다.

## 완료 조건

- [x] 문법과 CLI 계약이 `docs/` 아래 문서로 작성된다.
- [x] 후속 모델·파서·CLI task에서 사용할 결정 사항이 확정된다.

## 결정 사항

- MVP의 Gantt task 문법에는 `progress` 필드를 포함하지 않는다.
- task 상태는 `미진행`, `진행중`, `완료`, `보류` 네 값으로만 표현한다.
- 상태를 생략하면 `미진행`을 기본값으로 사용한다.
- 진행률이 필요해지면 기존 상태와 별개의 선택 필드로 확장한다.
- 문법보다 도메인 구조를 우선하며 날짜 구간 등 독립적인 값은 별도 모델로 표현한다.
- 입력 상태값은 `not_started`, `in_progress`, `completed`, `on_hold`로 고정하고 화면에서 한국어로 표시한다.
- MVP task는 `id`, `name`, `start`, `end`, `status`만 지원하고 사용자 지정 색상은 제외한다.
- 차트는 task만으로 구성할 수 있으며 milestone과 epic은 선택 항목이다.
- Epic은 task만 포함하고 milestone은 task 또는 epic을 포함할 수 있다.
- Epic과 milestone 진행률은 별도 필드로 입력받지 않고 모든 하위 `completed` task 수로 계산한다.
- MVP CLI는 `page <INPUT> [-o <OUTPUT>] [--format <html|pdf>] [--force] [--dry-run]` 형식을 사용한다.
- `--format html|pdf`로 출력 형식을 선택하고 기본값은 HTML로 한다.
- `--dry-run`은 문법·모델 정합성까지만 검사하고 출력 파일을 만들지 않는다.
- ID는 문서 전체에서 고유한 제한 문자열이며 명시 ID 예약 후 결정적으로 자동 생성한다.
- YAML 중복 key와 재사용 문법을 금지하고 날짜는 따옴표 문자열로 제한한다.
- 검증 오류는 가능한 범위에서 소스 순서로 수집하고 진단 코드 영역을 구분한다.
- 출력은 같은 디렉토리의 임시 파일을 거쳐 교체하며 실패 시 기존 파일을 보존한다.
- 결과 HTML은 UTF-8·LF로 직렬화하고 비결정적 메타데이터를 포함하지 않는다.

## 검증

- `docs/syntax.md`와 `docs/cli.md`를 작성했다.
- `docs/design.md`에는 제품 방향만 남기고 세부 모델은 `ep-0001/design.md`에 작성했다.
- 기존 제품 요구사항의 진행률·색상은 후속 편집 기능이며 생성기 MVP 모델에서는 제외됨을 구분했다.
- 선택적 milestone·epic 계층과 계산 진행률 규칙을 문법·요구사항·설계에 반영했다.
- ID, YAML 제한, 진단 코드, 오류 수집과 안전한 출력 정책을 계약 문서에 추가했다.
- HTML/PDF 출력 형식과 dry-run 정합성 검사 계약을 추가했다.
