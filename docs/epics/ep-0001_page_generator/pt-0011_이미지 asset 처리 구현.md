# pt-0011 이미지 asset 처리 구현

## 목표

Markdown 이미지가 `data:image` URI, 상대 파일 등 어떤 주소로 작성되어도 하나의 공통 처리 경로를 거쳐 단일 HTML 안에 `data:image` URI로 들어가게 한다.

## 작업 내용

- 이미지 내용을 가져오는 `AssetResolver` 인터페이스를 정의한다. `page-core`는 파일이나 네트워크를 직접 읽지 않고 이 인터페이스로 요청만 한다.
- `data:image` URI는 그대로 통과시키고, 그 밖의 주소는 resolver로 내용을 받아 공통 처리한다.
- 받은 바이트의 앞부분으로 이미지 형식(PNG, JPEG, GIF, WebP, SVG)을 확인하고 `DataImageUri`로 바꾼다.
- 가져오기·형식 확인 실패를 `PAGE106` 진단으로 바꾼다. 메시지로 원인(파일 없음, 형식 아님, 지원하지 않는 주소 등)을 구분한다.
- `CompileOptions`에 resolver를 넘기는 자리를 추가하고 design.md의 공개 API 계약을 갱신한다.
- `page-cli`에 md 파일 폴더를 기준으로 상대 파일을 읽는 resolver를 구현한다.
- 테스트용 메모리 resolver를 둔다.
- `docs/syntax.md`와 design.md의 "이미지는 `data:image`만 허용" 문구를 갱신한다.

## 완료 조건

- [ ] `![로고](./images/logo.png)`처럼 작성한 상대 파일 이미지가 단일 HTML 안에 `data:image` URI로 들어간다.
- [ ] 이미지 처리 실패가 원본 위치와 원인을 포함한 진단으로 반환된다.
- [ ] 이미지 출처가 늘어나도 resolver 구현만 추가하면 되는 경계가 마련된다.
- [ ] core 단위 테스트와 CLI resolver 테스트가 통과한다.

## 결정 사항

- 이미지 처리는 출처와 관계없이 공통 인터페이스 하나로 처리한다. 출처별 차이는 resolver 구현에만 둔다.
- pt-0004 파서는 이미지를 만나는 즉시 공통 처리를 호출한다. 실패 진단에 그 자리의 원본 위치를 바로 붙일 수 있으므로 이미지 참조의 위치를 따로 보존하지 않는다.
- pt-0003 모델은 바꾸지 않는다. `Inline::Image`는 처리가 끝난 `DataImageUri`만 담는다.
- 작업 진행 중 나머지를 기록한다.

### 결정 필요

- 인터넷 이미지(`https://…/a.png`) 처리: 오류와 함께 파일로 저장해 쓰도록 안내 / 주소 유지 / 변환 시 내려받기
- 상대 경로의 범위: md 파일 폴더 밖(`../`)과 절대 경로 허용 여부
- 이미지 크기 상한과 SVG 허용 범위
