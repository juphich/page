# 요구사항

## 1. 배경

간트차트나 보고서를 만들고 편집하려면 보통 전용 SaaS나 데스크톱 앱이 필요하다. 이 프로젝트는 Markdown 문서를 Rust 생성기로 PAGE HTML로 변환하고, 생성된 결과물을 **설치·계정·서버 없이** 브라우저에서 편집·전달·재편집할 수 있게 한다.

산출물은 언제나 **단일 HTML 파일**이다. 이 파일은 "결과물(보고서)"인 동시에 "편집기"다.

## 2. 원본 요구사항

1. Markdown 파일을 입력받아 최초 PAGE HTML 문서를 생성할 수 있다.
2. 생성기는 Rust로 작성한다.
3. page:gantt, page:chart, page:report 블록을 파싱하고 구성할 수 있다.
4. Mermaid의 플로우차트·UML 등 호환 블록을 처리할 수 있다.
5. 생성된 PAGE 문서는 스탠드얼론으로 독립 작동한다.
6. PAGE 문서는 단일 HTML 파일로 생성·저장·전달할 수 있다.
7. 생성된 HTML 문서는 JavaScript를 자체 내장하여 편집모드로 전환·편집할 수 있다.
8. 편집모드 편집은 별도 전용 툴 없이 브라우저 로컬에서 가능하다.
9. 온전한 PAGE 문서는 PDF로 출력할 수 있다.
10. 생성기는 기본 runtime을 내장한 단일 경량 실행 파일로 배포할 수 있다.
11. 별도 설정 없이 `page document.md`만으로 기본 스타일이 적용된 `document.html`을 생성할 수 있다.

## 2.1 Markdown 문서 블록

- 일반 Markdown은 제목·본문·표 등 일반 보고서 콘텐츠로 처리한다.
- page:gantt는 편집 가능한 간트 데이터 모델로 변환한다.
- page:chart는 데이터셋·차트 종류·시각화 옵션 모델로 변환한다.
- page:report는 구조화된 일반 보고서 모델로 변환한다.
- mermaid는 플로우차트·간트·UML 등의 호환 입력으로 처리한다.
- 변환할 수 없는 Mermaid 유형은 정적 결과물로 렌더링할 수 있다.

## 2.2 기본 스타일

- 모든 PAGE HTML은 별도 설정 없이 사용할 수 있는 기본 문서 스타일을 포함한다.
- 기본 스타일은 제목, 본문, 표, 인용구, 목록, 코드와 지원하는 PAGE 구성 요소를 표현한다.
- Gantt의 milestone, epic, task와 상태는 색상만이 아닌 계층과 비색상 표지로도 구분한다.
- 화면용 스타일과 인쇄/PDF용 스타일을 제공한다.
- 외부 stylesheet와 웹 폰트 없이 오프라인에서 동일하게 표시한다.
- 개발 소스에서는 스타일을 역할별 CSS로 분리하되 최종 산출물에는 모두 인라인한다.
- 사용자는 `--style`로 하나 이상의 CSS 파일을 지정할 수 있다.
- 사용자 CSS는 선언한 부분만 기본 스타일 위에 override하고 나머지 문서 스타일은 기본값을 유지한다.
- 사용자 CSS를 적용한 HTML과 PDF도 외부 stylesheet 없이 단일 파일이어야 한다.

## 3. 기능 요구사항


### 3.0 Rust 문서 생성기 (원본 생성)
- Rust CLI로 제공한다.
- 기본 HTML 셸, CSS와 JavaScript를 컴파일 시점에 실행 파일에 내장한다.
- 실행 시 별도 runtime 디렉터리나 필수 설정 파일을 요구하지 않는다.
- Markdown 파일 경로를 입력으로 받는다.
- fenced code block 유형을 식별하고 PAGE 중간 모델을 생성한다.
- 중간 모델과 PAGE 런타임을 단일 HTML에 포함한다.
- 생성된 HTML은 생성기·서버·네트워크 없이 브라우저에서 열려야 한다.
- PDF 엔진이나 브라우저를 실행 파일에 포함하지 않고 사용 가능한 로컬 Chromium 계열 브라우저를 호출한다.
- 기능이 중복되는 대형 runtime과 의존성을 피하고 release 바이너리 크기를 지속적으로 확인한다.

### 3.1 스탠드얼론 (요구 5)
- 외부 네트워크 요청 없이 동작한다. CDN·폰트·이미지 등 원격 리소스에 의존하지 않는다.
- `file://` 로 연 상태에서 모든 기능이 동작해야 한다.
- 모든 코드(HTML/CSS/JS)와 데이터가 단일 파일에 인라인된다.

### 3.2 내보내기 (요구 6)
- 현재 편집 상태를 완전한 HTML 문자열로 재조립해 파일로 저장한다.
- 저장된 파일은 원본과 동일하게 열리고 편집 가능해야 한다(왕복 안정성).

### 3.3 자체 내장 편집 (요구 7·8)
- 내보낸 파일 자체가 뷰어·에디터 JS를 품는다. 별도 도구·확장·서버 불필요.
- 보기 모드 ↔ 편집 모드 전환.
- 편집 기능:
  - 태스크 추가/삭제
  - 이름·시작일·종료일·상태 편집
  - 평면 task 목록과 선택적인 milestone·epic 계층 표시
  - 존재하는 Epic과 milestone의 완료 task 기반 진행률 표시
  - 막대 드래그로 이동, 양끝 리사이즈로 기간 조절
  - 차트 제목 편집
- 편집 결과는 다시 저장(3.2)으로 파일에 영속화된다.

### 3.4 PDF 출력 (요구 9)
- 브라우저 인쇄 기능으로 PDF 저장이 가능해야 한다.
- 인쇄 시 편집 UI(툴바·편집표·리사이즈 핸들)는 숨긴다.
- 색상·음영이 그대로 인쇄된다(print-color-adjust).

## 4. 비기능 요구사항

- **의존성 0**: 빌드 도구·프레임워크·런타임 없이 순수 웹 표준만 사용.
- **브라우저 호환**: Chrome/Edge(권장, 파일 덮어쓰기 저장), Firefox/Safari(다운로드 저장으로 폴백).
- **데이터 이식성**: 데이터는 파일 내 `<script type="application/json">`에 사람이 읽을 수 있는 형태로 보관.
- **안전한 왕복**: 저장 시 렌더링된 전이(transient) DOM 상태가 파일에 섞이지 않는다.

## 5. 범위 밖 (현 단계)

- 다중 사용자 실시간 협업, 서버 동기화
- 계정·권한·클라우드 저장
- 생성기와 PAGE 블록 내부 문법의 세부 구현(로드맵 대상)
- 자동 일정 계산(임계경로 등)
