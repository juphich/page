# PAGE 프로젝트 작업 규칙

## 작업 문서 위치

- 모든 작업 문서는 `docs/` 아래에서 관리한다.
- 모든 구현, 수정, 조사 작업은 epic을 기준으로 계획하고 기록한다.
- epic 문서는 `docs/epics/` 아래의 개별 epic 디렉토리에 보관한다.
- 종료된 epic은 해당 디렉토리 전체를 `docs/archive/` 아래로 이동해 보관한다.
- 프로젝트 backlog 문서는 `docs/backlogs/` 아래에 보관한다.

## Backlog 문서

- backlog 하나당 Markdown 파일 하나를 작성한다.
- 파일 이름은 `백로그_<제목>.md` 형식을 사용한다.
- 파일에는 해당 backlog의 배경, 목표, 범위와 기대 결과를 정의한다.
- 하나의 backlog 파일은 빈 줄을 포함해 최대 50줄을 넘지 않는다.
- 내용이 50줄을 넘거나 여러 목표가 섞여 있으면 그대로 확장하지 않는다. backlog 분할이 필요할 수 있음을 경고하고, 목표별 분할안을 제안한다.
- backlog는 향후 작업 후보의 정의이며 epic과 task 문서를 대신하지 않는다. 실제 작업을 시작할 때 관련 epic과 task를 구성한다.

```text
docs/backlogs/
└── 백로그_<제목>.md
```

## Epic 디렉토리

- 디렉토리 이름은 `<에픽코드>_<에픽제목>` 형식을 사용한다.
- epic의 목적, 범위, 완료 조건 등 기본 정의는 `index.md`에 작성한다.
- epic에 속한 전체 task와 진행 체크리스트는 `plan.md`에 작성한다.
- 개별 task 문서는 같은 epic 디렉토리 바로 아래에 작성한다.

```text
docs/epics/<에픽코드>_<에픽제목>/
├── index.md
├── plan.md
└── <티켓코드>_<태스크 제목>.md
```

## Epic 종료와 보관

- epic이 종료되면 `<에픽코드>_<에픽제목>` 디렉토리 전체를 `docs/epics/`에서 `docs/archive/`로 이동한다.
- 이동할 때 epic 디렉토리 이름과 내부 문서 구조를 유지한다.
- 종료된 epic 문서의 경로는 `docs/archive/<에픽코드>_<에픽제목>/`이다.

```text
docs/archive/<에픽코드>_<에픽제목>/
├── index.md
├── plan.md
└── <티켓코드>_<태스크 제목>.md
```

## Task 문서

- 파일 이름은 `<티켓코드>_<태스크 제목>.md` 형식을 사용한다.
- task는 반드시 해당 epic의 `plan.md`에 정의하고 체크리스트 항목으로 연결한다.
- 작업을 시작할 때 해당 체크리스트를 진행 상태로 갱신하고, 완료할 때 완료 상태와 결과를 반영한다.
- 구현 중 생긴 중요한 결정, 검증 결과, 후속 작업은 해당 task 문서에 기록한다.

## 적용 원칙

- backlog를 작성하거나 수정한 뒤 파일의 전체 줄 수가 50줄 이하인지 확인한다.
- 새 작업을 시작하기 전에 관련 epic과 task 문서가 있는지 확인한다.
- 관련 문서가 없으면 코드 변경보다 먼저 epic 디렉토리, `index.md`, `plan.md`, task 문서를 만든다.
- 기존 epic에 포함되는 작업이면 새 epic을 만들지 않고 해당 epic의 `plan.md`와 task 문서를 갱신한다.
- epic 종료 시 완료 상태를 문서에 반영한 뒤 epic 디렉토리를 `docs/archive/`로 이동한다.
- 범위가 불명확해 어느 epic에 속하는지 결정할 수 없으면 구현 전에 사용자에게 확인한다.
